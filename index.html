⚡ QueueGate — Ticket Queue Engine

GitHub
  • Engineered a distributed ticket-queue and reservation system that isolates the relational database from flash-sale surge traffic — ephemeral queue state lives entirely in Redis, while Postgres is touched only for event creation and confirmed bookings.
  • Eliminated check-then-act race conditions with 4 atomic Redis Lua scripts (queue join, batch admission, hold expiry, booking confirmation) executing inventory checks and hold transitions inside Redis's single-threaded engine — validated to 0.00% oversell under an adversarial test of 25 concurrent checkouts racing for 5 tickets.
  • Built a self-healing reconciliation worker that sweeps expired holds on a 5-second interval, atomically reclaims abandoned inventory, and cascades admission to the next waitlisted users — ensuring abandoned sessions never strand inventory.
  • Implemented real-time queue-position streaming with Socket.IO and the Redis Pub/Sub adapter, enabling stateless horizontal scaling without sticky sessions, with per-user/per-event room isolation.
  • Designed a state-partitioned write model where Redis confirms the hold atomically before the Postgres insert, backed by compound unique constraints and unique-violation handling as a final defense against duplicate bookings.
  • Authored an automated concurrency benchmark suite simulating a 200-client simultaneous join burst followed by synchronized double-booking attempts, measuring 1,198 req/sec sustained across the 200-client join burst.
